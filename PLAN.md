# План реализации: TGGATE — Telegram Gate
## Панель управления Telemt (Web Proxy + MTProto)

Источники требований: `промт для панели.md.txt`, `Дополнение.md`

## 🏷️ Брендинг (зафиксировано)
- Название проекта: **TGGATE** (Telegram Gate)
- Репозиторий панели: `https://github.com/Therealwh/Web-Proxy-Telegram-Panel-TG-BOT`
- Репозиторий Telemt: `https://github.com/telemt/telemt`
- Команда управления: `sudo TGGATE` (скрипт `tggate.sh`, НЕ wpp.sh)
- Пути: `/etc/tggate/`, бэкапы в `/var/backups/tggate/`
- Systemd: `tggate-panel.service`, `telemt.service`
- Пользователь ОС: `tggate`
- Шапка панели: TGGATE + subtitle «Telegram Gate — панель управления прокси»
- Футер: `© 2026 TGGATE | Версия 1.0.0 | Работает на Telemt`
- Favicon: ворота/шлюз + символ Telegram; `<title>TGGATE</title>`

## 0. Подготовка
- [ ] Стек backend: Node.js + Express + SQLite (better-sqlite3)
- [ ] Стек frontend: React 18 + Vite, Tailwind CSS, shadcn/ui (Radix UI), Recharts, Zustand, CodeMirror 6, socket.io (или нативный WS), qrcode.react, react-hook-form + zod, Lucide React
- [ ] Telegram-бот: **grammY (Node.js)** — единый стек с панелью; примеры для разработчиков давать на Python (aiogram) и Node.js
- [ ] Инфраструктура: Caddy (HTTPS + заглушка), Nginx (reverse proxy), systemd, UFW
- [ ] Структура репозитория по промту: `/install.sh`, `/tggate.sh`, `/update.sh`, `/uninstall.sh`, `/panel/`, `/scripts/`, `/templates/`, `/systemd/`, `/docs/`
- [ ] `.gitignore`, `LICENSE` (MIT), `CHANGELOG.md`, черновик `README.md`
- [ ] Стиль именования: camelCase (JS), PascalCase (React), snake_case (SQL), kebab-case (файлы/URL)

## 1. Установщик (install.sh + scripts/)
- [ ] `install.sh` — интерактив: домен, email для Let's Encrypt, логин/пароль админа (проверка сложности ≥8 символов), внешний IP (автоопределение + переопределение)
- [ ] Проверки: root, чистый VPS (порты 80/443 свободны), Ubuntu 22.04/24.04
- [ ] **Проверка DNS**: A-запись домена существует и указывает на IP сервера; предупреждение + повтор проверки; опционально доступность 80/443 извне
- [ ] `scripts/setup_firewall.sh` — UFW: 80/tcp, 443/tcp, 8443/tcp
- [ ] `scripts/install_telemt.sh`:
  - [ ] Фиксация версии Telemt (например 3.5.5+), скачивание бинарника из официальных релизов
  - [ ] Проверка архитектуры (x86_64 / aarch64) и контрольной суммы SHA-256
  - [ ] Установка в `/usr/local/bin/telemt`, отдельный пользователь ОС, конфиг из шаблона (Web Proxy + MTProto :8443)
- [ ] `scripts/install_caddy.sh` — HTTPS, сайт-заглушка на домене
- [ ] `scripts/install_nginx.sh` — reverse proxy к панели, секретный путь админки (не /admin)
- [ ] `systemd/telemt.service`, `systemd/tggate-panel.service`
- [ ] `tggate.sh` — меню управления (статус, старт/стоп/рестарт, логи, смена логина/пароля, смена домена, обновления панели/Telemt, проверка обновлений, бэкап, восстановление, удаление); alias `sudo TGGATE`
- [ ] `update.sh`, `uninstall.sh` (полное удаление)

- [ ] Валидация всех входных данных (zod), параметризованные SQL-запросы, экранирование вывода
- [ ] **Миграции БД**: `/migrations/*.sql`, таблица `schema_version`, автоприменение при старте, автобэкап БД ПЕРЕД миграциями, откат при ошибке

## 📌 Золотые правила (применять всегда)
1. «Работает — не значит готово»: код красивый, поддерживаемый, модульный (SOLID, DRY)
2. «Пользователь не программист»: понятные сообщения и подсказки
3. «Русский — это важно»: UI, документация, комментарии, ошибки — на русском
4. «Безопасность по умолчанию»
5. «Красивый код = счастливый разработчик»
6. «Одна команда — один результат»
7. «Документация — часть продукта»
8. «Интернет — твой друг»: проверять актуальность, адаптировать под TGGATE, ссылки-источники в комментариях
9. «Делай красиво»: код, UI, документация
10. «TGGATE — это продукт, а не скрипт»
