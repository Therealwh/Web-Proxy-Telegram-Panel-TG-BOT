## ⚡ Быстрая установка

Требования: чистый VPS с **Ubuntu 22.04 / 24.04**, root-доступ, домен с
A-записью на IP сервера.

```bash
apt-get -o DPkg::Lock::Timeout=600 update && \
apt-get -o DPkg::Lock::Timeout=600 install -y curl ca-certificates git && \
bash -c "$(curl -fsSL --proto '=https' --tlsv1.2 \
  https://raw.githubusercontent.com/Therealwh/Web-Proxy-Telegram-Panel-TG-BOT/main/install.sh)"
```

Установщик интерактивно спросит:

| Параметр | Описание |
|---|---|
| 🌐 Домен | Например, `proxy.example.com` (A-запись должна указывать на сервер) |
| 📧 Email | Для SSL-сертификата Let's Encrypt |
| 👤 Логин | Логин администратора (латиница) |
| 🔑 Пароль | Минимум 8 символов, буквы + цифры |
| 🌍 IP | Внешний IP (определяется автоматически) |

После установки вы получите адрес панели с секретным путём:
`https://ваш-домен/cp-xxxxxx/`

Дальше пройдите шаги из карточки **«Первоначальная настройка»** на дашборде —
панель подскажет, что осталось настроить.

## 🤖 Telegram-бот продаж

Тарифы с ценами и лимитами (IP, трафик), выдача ссылок после оплаты,
уведомления админу, статистика продаж. Админка в самом боте: `/admin` —
дашборд, подтверждение платежей, рассылки.

**Способы оплаты:** баланс, CryptoBot, ЮKassa, ⭐ Telegram Stars
(автоконверт цены по курсу), карта админа (СБП) с приёмом чеков.

**Личный кабинет:** все прокси клиента — под каждым кнопки
«🌐 Подключить ВЕБ прокси» / «🔌 Подключить MTProto прокси» (по купленным
протоколам) и «♻️ Продлить». Продление прокси с двумя протоколами
(например, тестового) предлагает выбор: только Web / только MTProto / оба.
**Автопродление с баланса** — включается клиентом одним нажатием.
Плюс пополнение баланса, рефералка и пошаговые инструкции «📱 Как подключить».

**Веб-кабинет:** ссылка `/p/{токен}` приходит с каждой покупкой — клиент
видит прокси и продлевает с оплатой прямо в браузере, даже если удалил бота.

Обязательная подписка на канал (вкл/выкл), тестовый доступ на 3 часа.

**Надёжность:** автобэкап базы в Telegram, мониторинг MTProto/Web/Telemt
с алертами в бот, публичная страница статуса, iOS-подсказки при подключении.

## 🛡 Защита и отказоустойчивость

Настройки собраны в одном разделе (**Настройки → Защита и отказоустойчивость**).
Большинство из них применяется с перезапуском движка — об этом сказано на карточке.

### Fake TLS (MTProto)
Панель генерирует ссылки Fake TLS (`ee`) **в дополнение** к обычным (`dd`),
а не вместо них. Уже выданные клиентам ссылки не меняются и продолжают
работать — клиент просто получает вторую ссылку и выбирает, что работает
у его оператора.

Ссылка `ee` появляется только после проверки домена маскировки: он должен
поддерживать **TLS 1.3** и резолвиться в **IP этого сервера**. Если проверка
не пройдена, `ee`-ссылка не показывается вовсе — вместо неё клиент видит
рабочую `dd`. Проверка выполняется раз в 6 часов и после смены домена маскировки.

> Fake TLS относится только к MTProto. Web Proxy уже работает поверх
> настоящего HTTPS и в нём не нуждается.

### Запасные транспорты Web Proxy
Панель может включить перебор транспортов: клиент пробует их по порядку,
пока не найдёт рабочий (`https-lanes`, `websocket`, `websocket-lanes`).
Запасным вариантом всегда остаётся `https` — **Telegram iOS поддерживает
только его**, и его смена сломала бы весь iOS.

Перебор выключен по умолчанию. Учтите: параметр не поддерживает hot-reload,
поэтому после применения панель перезапускает движок.

### Политика SNI
Настраивается, что движок отвечает клиенту, пришедшему с чужим SNI:

| Поведение | Описание |
|-----------|----------|
| `drop` | Молча закрыть соединение (по умолчанию) |
| `mask` | Перенаправить на маску — максимальная маскировка |
| `accept` | Принять как валидный (слабее защита от пробинга) |
| `reject_handshake` | Отказать рукопожатием, как nginx без такого домена |

### Живой сайт за прокси-доменом (selfmask)
Вместо заглушки панели можно отдавать настоящий сайт: обычные запросы
к прокси-домену перенаправляются на локальный бэкенд. Указывается **приватный
адрес** (например `127.0.0.1:8099`) — движок принимает только `http://`
с IP-литералом приватной или локальной сети.

### Запасные домены
Дополнительные домены работают на том же IP и том же секрете клиента.
Если основной домен заблокируют, клиент переключается на резервный.

Ограничения движка, о которых стоит знать заранее:
- максимум **8 доменов**;
- каждому домену нужны собственные профили клиентов, а всего профилей
  допускается **32** — каждый новый домен умножает их число. Панель
  предупредит об этом до применения;
- домен должен **уже указывать на IP сервера**, иначе Let's Encrypt
  не выпустит сертификат и подключение не заработает.

### Блокировка IP и подсетей
Список адресов и подсетей в формате CIDR. Правила применяются двумя
механизмами: `deny` в Nginx для веб-прокси и наборы nftables для порта
MTProto — пакеты отсекаются до попадания в движок.

**Панель и SSH под блокировку не попадают:** у панели собственный location,
у MTProto свой порт. Иначе заблокированный адрес потерял бы ещё и доступ
к админке.

Слишком широкие подсети (IPv4 шире `/8`, IPv6 шире `/16`) отклоняются —
иначе один неверно введённый адрес отрезал бы доступ к прокси огромной
части клиентов.

### Резервный маршрут к Telegram (WARP)

Если доступ с IP сервера к адресам Telegram DC закрывается, клиенты
подключаются к прокси, но **ничего не грузится**: обрыв на участке
«сервер → Telegram». Перезапуск движка не помогает — маршрут тот же,
и DC-монитор такое состояние видит, но обойти не может.

Резерв заворачивает в туннель Cloudflare **только трафик к дата-центрам
Telegram**. Весь остальной трафик (панель, сайты, обновления) идёт
напрямую и не зависит от Cloudflare.

Выключено по умолчанию, включается одним кликом
(**Настройки → Защита → Резервный маршрут**).

Как пользоваться:
1. Поставить клиент Cloudflare WARP на сервер и зарегистрировать аккаунт.
2. Включить резерв в панели — добавятся правила маршрутизации к подсетям Telegram.
3. Если клиенты жалуются «подключается, но не грузит» — включить.
4. Если всё работает и без него — держать выключенным: WARP добавляет
   задержку и не нужен, пока нет проблемы.

Если правила включены, а туннель отключён — панель покажет это отдельным
предупреждением: такой маршрут хуже отсутствия маршрута, трафик к
Telegram уходит в никуда.

Вручную:
```bash
sudo bash /opt/tggate/scripts/warp.sh status|enable|disable
```

### Лимиты памяти и CPU
Движок ограничивается через systemd drop-in, который переживает обновления
движка. Лимиты считаются от фактической памяти сервера, а не задаются
мегабайтами вручную.

`MemoryMax` ограничивает **только процессы Telemt**: при его достижении
перезапустится движок, а панель, Nginx и Caddy останутся доступны. Без
потолка OOM-killer выбирает жертву наугад и может убить панель.

Применить: **Настройки → Защита → Лимиты памяти и CPU**, либо вручную:
```bash
sudo bash /opt/tggate/scripts/telemt-limits.sh
```

Текущее потребление и процент от потолка видны в **Диагностике**.

## 🔄 Обновления

### Автоматические
Панель проверяет обновления с заданной частотой
(Настройки → Обновления). Каналы: stable / beta / latest.

### Ручные
- Через панель: **Обновления → Обновить панель / Обновить Telemt**
- Через консоль: `sudo TGGATE` → пункты 8/9/10

```bash
# или напрямую, с указанием версии
sudo bash /opt/tggate/scripts/update-panel.sh v1.17.0
```

### Откат
При неудачном обновлении панель автоматически откатывается на бэкап.
Бэкапы хранятся в `/var/backups/tggate/`, ротация оставляет последние три.

## 🔧 Troubleshooting

| Проблема | Решение |
|---|---|
| Панель не открывается | Проверьте секретный путь и `sudo TGGATE` → статус |
| SSL не выпускается | Убедитесь, что A-запись домена указывает на IP сервера |
| MTProto не подключается | `sudo ufw status` — порт 8443 должен быть открыт |
| Telemt упал | `journalctl -u telemt -n 100` |
| Непонятно, что сломано | **Проверка системы** в панели — собирает всё в одном месте |
